# Работа №1: DES, DEAL и режимы симметричного шифрования

Все семь пунктов реализованы на C#/.NET 8 без внешних пакетов. DES, DEAL,
режимы и набивки написаны самостоятельно. Из `System.Security.Cryptography`
используется только генератор случайных байтов для ISO 10126.

## 1.2. Контекст шифрования

`IKeyExpander`, `IRoundTransformation`, `ISymmetricCipher` задают расширение
ключа, раундовую функцию и блочный шифр. `SymmetricCipherContext` принимает
реализацию шифра, ключ, режим, набивку, необязательный IV и дополнительные
параметры режима через `params object[]`. Ключ настраивается при создании.
Переданный экземпляр шифра принадлежит контексту: после этого не следует
вызывать его `SetKey` или передавать другому контексту. Блочные операции
DES и DEAL с уже заданным ключом допускают одновременные вызовы.

```csharp
using CryptoLab;

var key = Convert.FromHexString("133457799BBCDFF1");
var iv = Convert.FromHexString("0102030405060708");
var context = new SymmetricCipherContext(
    new DesCipher(), key, EncryptionMode.Cbc, PaddingMode.Pkcs7, iv);

byte[] data = [1, 2, 3, 0, 0];
byte[] encrypted = await context.EncryptAsync(data);
byte[] restored = await context.DecryptAsync(encrypted);

var output = new byte[context.GetCiphertextLength(data.Length)];
int bytesWritten = await context.EncryptAsync(data, output);

await context.EncryptAsync("input.bin", "input.bin.enc");
await context.DecryptAsync("input.bin.enc", "restored.bin");
```

В C# асинхронные методы не допускают `ref`/`out`, поэтому результат
возвращается как `Task<byte[]>` либо записывается в переданный массив
с возвратом числа записанных байтов как `Task<int>`.

Вычисления запускаются через `Task.Run`, файловые чтение и запись используют
асинхронный `FileStream`. Файлы обрабатываются порциями по 4096 блоков;
целиком загружать музыку или видео в память не требуется. Состояние сцепления
сохраняется между порциями и создаётся заново для каждого вызова. Методы
принимают `CancellationToken`. Файловый результат сначала пишется во временный
файл и заменяет выходной только после успешного завершения. Входной и выходной
пути должны различаться.

### Режимы и параллельность

`P_i` - открытый блок, `C_i` - шифрованный блок, `E`/`D` - блочные
шифрование/дешифрование, `xor` - исключающее ИЛИ. Первый индекс равен 0.

| Режим | Формула шифрования | Что распараллелено |
| --- | --- | --- |
| ECB | `C_i = E(P_i)` | Шифрование и дешифрование |
| CBC | `C_i = E(P_i xor C_(i-1))`, `C_-1 = IV` | Дешифрование |
| PCBC | `C_i = E(P_i xor S_i)`, `S_0 = IV`, `S_(i+1) = P_i xor C_i` | Последовательный в обе стороны |
| CFB | `C_i = P_i xor E(C_(i-1))`, `C_-1 = IV` | Дешифрование |
| OFB | `S_i = E(S_(i-1))`, `S_-1 = IV`, `C_i = P_i xor S_i` | Последовательная генерация гаммы |
| CTR | `C_i = P_i xor E((IV + i) mod 2^b)` | Шифрование и дешифрование |
| Random Delta | `C_i = E(P_i xor ((IV + i * delta) mod 2^b))` | Шифрование и дешифрование |

CFB использует целый блок обратной связи (CFB-64 для DES, CFB-128 для DEAL).
Для CFB, OFB и CTR при расшифровке тоже используется **E**, а не D.
По условию выбранная набивка применяется ко всем семи режимам.

В задании не приведена формула Random Delta. Здесь явно зафиксирован
вариант со сложением маски и шифрованием `P_i xor mask_i`; обратное
преобразование - `D(C_i) xor mask_i`. IV и delta передаются отдельно и не
добавляются в шифротекст. Delta - дополнительный параметр, массив размером
в блок. Она должна быть нечётной, чтобы период масок составлял `2^b`.
Счётчик и delta - беззнаковые числа big-endian; `b` - размер блока в битах.
Повторение счётчика внутри операции запрещено.

```csharp
var delta = Convert.FromHexString("0000000000000003");
var rd = new SymmetricCipherContext(new DesCipher(), key,
    EncryptionMode.RandomDelta, PaddingMode.Pkcs7, iv, delta);
```

Для ECB IV необязателен. Остальные режимы требуют IV размером ровно в блок.
Шифротекст содержит только блоки; при расшифровке используются те же алгоритм,
ключ, режим, набивка, IV и delta. В демонстрации они сохранены в `manifest.json`.
Параллельные блоки выполняются через `Parallel.For`; число потоков задаётся
свойством `MaxDegreeOfParallelism` (1 для последовательной проверки,
по умолчанию число логических процессоров).

### Набивки

| Набивка | Добавляемые байты при длине набивки `n` |
| --- | --- |
| Zeros | `00 ... 00`; полный блок при выровненной длине не добавляется |
| ANSI X.923 | `00 ... 00 n` |
| PKCS7 | `n n ... n` |
| ISO 10126 | `random ... random n` |

Последние три всегда добавляют хотя бы один байт, включая полный блок
для пустых или уже выровненных данных. При снятии проверяется длина набивки,
для PKCS7 и ANSI X.923 - также содержимое. У ISO 10126 байты перед последним
произвольные, поэтому проверить можно только длину.

Для Zeros **обязательно** передать `originalLength`: нулевые байты могут
быть частью исходных данных. Контекст проверяет длину и нули набивки.

```csharp
var zeros = new SymmetricCipherContext(new DesCipher(), key,
    EncryptionMode.Cbc, PaddingMode.Zeros, iv);
var ciphertext = await zeros.EncryptAsync(data);
var plaintext = await zeros.DecryptAsync(ciphertext, originalLength: data.Length);
await zeros.DecryptAsync("file.enc", "file.restored", originalLength: 12345);
```

## 1.6. DEAL

Блок DEAL - 16 байт. Ключи 16 и 24 байта дают 6 раундов, ключ 32 байта -
8 раундов. `DesRoundAdapter` реализует `IRoundTransformation` через собственный
`DesCipher`: F - **полное шифрование DES** 8-байтовой половины под 8-байтовым
раундовым ключом.

Реализация следует исходному отчёту Ларса Кнудсена
[DEAL - A 128-bit Block Cipher, 21.02.1998](https://www.nic.funet.fi/~bande/docs/crypt/system/deal.ps.gz),
разделам 2 и 2.1. Половины обновляются по формулам
`L_new = DES_RK(L) xor R`, `R_new = L`; перестановка после последнего раунда
сохраняется. Существующая сеть Фейстеля обрабатывает правую половину,
поэтому `DealCipher` меняет половины перед её вызовом и после него.

Для расширения ключ делится на `s` частей `K_i` по 8 байт. Генерируются
`r` ключей: `RK_i = DES_fixed(K_(i mod s) xor RK_(i-1) xor constant_i)`.
Начальное `RK_-1 = 0`, фиксированный DES-ключ `0123456789ABCDEF`.
Первые `s` констант нулевые, последующие - целые числа 1, 2, 4, 8
в 64-битном big-endian представлении, как определено в этом отчёте.
Биты чётности сохраняются при цепочном расширении; DES исключает их своим
PC-1 при использовании результата как DES-ключа.

## Проверки

`Demo/Checks.cs` дополняет исходные проверки пунктов 1.1, 1.3, 1.4:

- Известный вектор DES: ключ `133457799BBCDFF1`,
  `0123456789ABCDEF -> 85E813540F0AB405`.
- Все размеры ключа DEAL, число раундов, адаптер и прямые уравнения из отчёта,
  сопоставленные с результатом переиспользованной сети Фейстеля.
- 392 сочетания алгоритма, режима, набивки и длины массива: пустой,
  неполный, полный и несколько блоков; нулевые байты в конце.
- Формулы каждого режима, перенос счётчика CTR и шаг Random Delta.
- Совпадение параллельной и последовательной обработки; одновременные
  операции одного контекста; перегрузки с выходным массивом.
- Файлы на границах порций 32768 байт для всех 28 сочетаний DES и
  отдельная проверка DEAL на 65537 байтах; совпадение с обработкой массива.
- Неверные ключи, IV, delta, длины блоков, повреждённая набивка,
  маленький выходной массив, отмена и сохранение выходного файла при ошибке.

Напечатанные векторы DEAL вычислены этой программой и сверены с прямыми
формулами отчёта; они не объявляются внешними официальными тестовыми векторами.

Для защиты: интерфейсы -> сеть Фейстеля -> DES -> контекст и зависимости
между блоками -> набивки -> адаптер и расписание DEAL -> демонстрация
побайтного восстановления файлов во всех режимах.
